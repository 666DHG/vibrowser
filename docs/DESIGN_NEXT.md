# 下一步计划与目标

日期：2026-11-07。实验分支：feat/content-driven-design。目的：提高跨站视觉差异与真实交互完成度，并提供标准／深入两挡思考。本文是实施与测试计划；本轮先执行现有行为的基线测试，不把尚未实现的开关记为通过。

## 已知证据与边界

11 月 7 日六个任务中，五个保留初稿，一个采用改进稿；四次改进被保护检查拒绝，一次评审无问题。六个初稿已具有近白／米白背景和红色／红棕强调色。唯一被采用的改进没有改变字体或配色。三个日期任务包含一次父子导航，不能当作三个独立网站；共五个入口任务、四个不同输入字符串，样本不足以断言所有网站都会趋同。

现有保护检查要求动作和字段绑定对象完全相同，正文按长度至少 12 字符的叶节点字符串做集合交集。它保护事实与功能的意图正确，但可能阻止动作纠错、正文拆段和标记重排。KFC 样本用 Set 输出“已复制”，没有剪贴板动作；日期页评审把打开新页面的 Search 当作需要本页结果区域。评审意见不能直接视为事实。

## 目标一：功能修复可验证，评审不统一审美

1. 为评审问题增加封闭类别（交互、可读性、布局、内容）、相关元素及动作 ID、证据与拟修改范围。可选审美建议不得触发强制重写。
2. 建立动作行为契约：Search 打开站内结果页；Set 只修改状态文本；Toggle 必须有可触发控件与有效区域。复制能力选择真实实现后再开放，不允许把状态提示当成复制成功。
3. 改进允许对明确指出的失效绑定做限定修复，保留动作身份和用户意图；验证目标、事件触发、数据与区域，禁止整体放松校验。
4. 正文保护改为内容区文本顺序／覆盖及实体事实检查，允许拆段与内联标记变化。导航、按钮标签与生成提示不充当正文覆盖；删除正文、改写已知实体仍拒绝。
5. 宿主将当前日期、时区及日期导航目标作为明确上下文。相对日期必须有可解析基准；修复之后前后日导航需验证日期确实变化。

验收：复制真实写入且失败不显示成功；失效 Toggle 能修复并触发；正文重排不误拒，删除正文与改事实仍拒；Search 不再被要求提供本页 region；无效修复回退原页且记录原因。

## 目标二：内容决定设计，不引入风格菜单

设计说明区分新站与同站：新站自主提出与内容和站点身份有关的视觉表达，不能虚构已有品牌；同站继承实际保存的视觉语言。去掉将低装饰、克制、窄栏、单强调色作为普遍优点的诱导，也不反向要求所有页面夸张。字体、密度、导航、首屏和版式必须对应此页任务，不按类别指定组件。评审只纠正具体问题，不能仅因风格特殊要求统一成文档页。

首次对照使用六个固定主题：学术主页、梗文案工具、日期日历、器具对比、技术文档、个人随笔。同主题固定输入与来源，保存初稿、评审、改进稿。人工比较信息架构、阅读节奏、字体层级、导航与首屏；颜色差异不单独算多样性，是否命中某个模板不作为指标。

验收：至少四组存在与任务相关的实质结构／排版改善，其余无功能或阅读退步；跨站不能只换文案与颜色，同站详情仍延续身份。每个主题至少跑一条真实交互；不得重跑直到挑出好看样本。

## 目标三：两挡思考，与幻觉／认真正交

UI：地址栏显示“幻觉／认真”和“标准／深入”两个独立选择，窄屏可折叠在同一个菜单但两项值都可读。默认标准；标签保存选择，新标签继承。提交时写入任务快照，切换不改变在途任务，重试使用原档位。页面内动作沿用页面档位；历史／书签恢复原页面记录，改变档位不改写缓存。

| 档位 | 官方 DeepSeek 请求 | 工作流 |
| --- | --- | --- |
| 标准 | thinking.type=disabled | 设计简报、生成、测量、单次评审、至多一次改进 |
| 深入 | thinking.type=enabled，reasoning_effort=high | 相同流程、相同硬性校验与模型请求次数上限 |

两挡先只改变模型内部思考投入，不把深入等同于更多轮次、随机换风格或更多搜索。连接测试仍使用小型标准请求。Search/Fetch 没有思考档位参数；检索规划的模型请求采用任务档位。

数据按课程规范增加独立 GenerationEffort enum、请求可选字段、页面与任务记录，旧记录归 standard；前端 API 类与 send 保持一致。档位参与在途任务去重；书签按保存页面 ID 读取，不因选择变化重新生成。同一书签打开仍为零模型请求。

服务能力单独建模：官方启用已核验参数；TokenHub／自定义在验证前不发送假定兼容的私有字段，UI 明确显示支持状态。禁止静默忽略深入请求。保存实际参数摘要、模型、耗时、token 用量和失败原因，不保存密钥或公开模型内部思考文本。思考可能占用输出预算，须验证 JSON 完整性并区分推理与最终内容；先测再定深入档总时限，不简单套用简报 60 秒导致系统性超时。

参数依据：DeepSeek 官方 Thinking Mode 文档 https://api-docs.deepseek.com/guides/thinking_mode/ ，2026-11-07 核验；支持 enabled/disabled 与 low/high/max。参数可用不代表当前应用已接入，也不代表深入必然更好。

## 测试与提交顺序

1. **基线（本轮）**：只读保存近期任务摘要；复现假复制、动作纠错被拒、相同正文拆段被拒；运行现有工作流／provider 测试、前端检查和测量测试。保留真实问题，不将复现断言通过解释为产品功能通过。
2. **修复契约**：实现目标一；失败 fixtures → 修复 → 浏览器行为验证后提交。补齐旧格式、回退、重试、事务与权限回归。
3. **设计指导**：实现目标二，先固定标准档，六个主题新旧对照；认真模式共用检索快照，记录初稿与改进稿，避免混入档位变量。
4. **两挡实现**：任务与会话持久化、兼容能力、参数、UI 后提交。自动检查参数映射、后台任务隔离、连续切换、重试、旧会话、书签和不可用接口。
5. **档位实验**：固定新指导与同一来源，六主题各标准／深入一次，共十二个初始任务；测首轮成功率、有限修复后成功率、控件可用率、耗时／token／请求数，不要求百分百事实正确。再选同站详情核对继承。失败原样记录，仅针对明确修复做一次复测。

最终交付：分阶段提交、两挡可操作 UI、回归报告、真实任务 ID、参数摘要与截图。若深入没有稳定收益，保留可选档位并说明证据，不为通过实验改门槛；设计指导是否默认开启另按其对照门槛判定。

## 本轮基线结果

本轮未修改生产逻辑；新档位与指导调整尚未实现，没有发起额外付费生成。测试使用真实保存的 HTML，在隔离浏览器内回放，未读取或改写用户剪贴板。

| 检查 | 结果及含义 |
| --- | --- |
| 六个近期任务前后比较 | 五个最终 HTML/CSS 与初稿完全相同；风格趋同并非主要由评审改写造成 |
| 真实 KFC 页复制按钮 | 点击后显示“已复制，可以直接发出去”，剪贴板 API/旧式 copy 调用数均为 0，服务端动作数为 0；假复制问题确认 |
| 正文排版保护 | Jsoup 提取的可读正文完全相同，拆成两个 span 后仍被拒；误判确认 |
| 动作保护 | 保留动作 ID 和功能，将错误的触发元素恢复为正确按钮仍被拒；误判确认 |
| 官方模型请求 | 普通生成请求固定 thinking=disabled 且没有 reasoning_effort；目前没有两挡能力 |
| Scala 定向测试 | 13 项通过：2 项已知问题复现、6 项设计流程/数据库、5 项 provider；修改普通请求参数断言后，provider 5 项再次通过 |
| 前端与测量 | 42 项单测、2 项 Chromium 测量测试、格式/类型/生产构建通过 |

证据：[近期历史与复制回放](acceptance/design-baseline-2026-11-07.json)。复现套件名明确为 Baseline；修复时必须将对应断言改成期望接受正确修改，不能长期以复现缺陷当作发布验收。没有重跑全量浏览器回归，也没有测试尚不存在的深入档。
